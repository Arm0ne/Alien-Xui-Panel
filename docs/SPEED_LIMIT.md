# 入站限速（端口级）

## 功能说明

在「入站 → 编辑」里填 **入站限速（Mbps）** 即可。规则如下：

- **粒度**：整个入站端口。也就是说，该入站下的所有用户**共享**这一个带宽额度。
- **方向**：只限制下行（服务器 → 客户端），匹配的是「源端口 = 入站端口」的报文。
- **单位**：Mbps。填 `0` 表示不限速。

## 为什么用 tc 而不是 Xray

早期版本是把客户端的 `speedLimit` 当成 Xray 的 policy level 下发的，这**不可能生效**：
Xray-core 的 `policy.levels` 里只有「连接超时」和「统计开关」，
其中 `uplinkOnly` / `downlinkOnly` 的单位是**秒**（单向静默多久断连），跟带宽无关。

所以限速改由内核的 tc（HTB 队列）完成，Xray 配置里不再生成任何「伪限速」字段。

## 工作原理

- 面板每 10 秒对账一次（`web/job/speed_limit_job.go`），只有配置变化时才下发命令；
- 网卡自动取「默认路由所在网卡」（读 `/proc/net/route`），不会写死成 `eth0`；
- 每个不同的限速值对应一个 HTB class，每个入站端口对应一条 filter：
  `match ip sport <入站端口>` → 对应的 classid；
- 其他流量（包括没限速的入站）走默认 class，不受影响；
- 默认 class 的速率固定为 **25Gbit**（远大于真实网卡带宽，等效于不限速）：不读取网卡速率，避免虚拟网卡上报异常值把不限速的流量压住；
- 面板正常退出、或所有限速都被取消时，会清理面板自己下发的规则。

注意：限速会接管出口网卡的根 qdisc，之前手工加在 `eth0` 上的 tc 规则会被替换掉。

## 依赖

- Linux + root 权限（面板本来就以 root 运行）
- `tc`（由 `iproute2` 提供）——`install.sh` 已自动安装
- 内核 `sch_htb` 模块（几乎所有发行版自带）

## 验证是否生效

```bash
# 1. 看 class：rate 应该等于你填的限速值，bytes 应该持续增长
tc -s class show dev eth0

# 2. 看 filter：sport 应该是入站端口，flowid 指向上面的 class
tc filter show dev eth0

# 3. 看面板日志
journalctl -u x-ui -f | grep 限速
```

客户端做一次测速，下载速度应该稳定在设定值附近（TCP 会有一定浮动，属正常）。

## 故障排查

| 现象 | 原因 / 处理 |
| --- | --- |
| 日志提示找不到 `tc` | 安装 iproute2：`apt install -y iproute2`（或 `yum install -y iproute`） |
| 提示 `Unknown qdisc "htb"` | 内核缺 `sch_htb`：`modprobe sch_htb`（Alpine 需先装 `kmod`） |
| 规则下发成功但速度没降 | 确认测的是**下行**；核对 filter 里的 `sport` 是否等于入站端口；用 `tc -s class show` 看 bytes |
| 日志提示「未找到默认路由网卡」 | 服务器没有默认路由（特殊网络环境），需要在面板里手工指定网卡（当前未实现，可反馈） |
| 改了配置 10 秒内没生效 | 对账周期是 10 秒，稍等即可；也可看日志确认是否已下发 |

## 关闭限速

- 把「入站限速」改成 `0` 保存，10 秒内该端口的规则会被移除；
- 如果所有入站都不限速，面板会删除自己建立的根 qdisc，恢复网卡原状。

## 历史遗留

- 客户端级的「独立限速」字段已删除（Xray 不支持该能力，填了也不会生效）；
- 旧数据中可能残留 `speedLimit` 字段，不影响运行，也不会再写入新数据。
